# 13 — MBC1

## Goal

Bank ROM (and SRAM if present) through MBC1. **Super Mario Land** (or another MBC1 title) boots. Tetris still works (type `$00` bypasses the mapper).

## Why

The CPU can only see 32 KiB of cartridge ROM at once. MBC1 lets a 64 KiB–2 MiB chip switch 16 KiB pages into `$4000–$7FFF`. Super Mario Land is 64 KiB (`$0148 = $01`) with no SRAM — the smallest interesting MBC1 test. Dr. Mario is **not** MBC1; it already ran in chapter 12.

## Design

Replace “ROM is a flat `Uint8Array`” with a `cart` object:

```js
export function createCart(rom) {
  const header = parseHeader(rom);
  if (header.type === 0x00) return createRomOnly(rom);
  if ([0x01, 0x02, 0x03].includes(header.type)) return createMbc1(rom, header);
  throw new Error(`mapper ${header.typeName} not implemented`);
}
```

Bus ROM range delegates:

```js
if (addr < 0x8000) return cart.readRom(addr);
if (addr < 0xa000) …
if (addr < 0xc000) return cart.readRam(addr);
// writes:
if (addr < 0x8000) cart.writeRom(addr, v);
if (addr >= 0xa000 && addr < 0xc000) cart.writeRam(addr, v);
```

ROM-only `writeRom` is a no-op.

## MBC1 logic

Full register map: [docs/reference/mbc.md](../docs/reference/mbc.md).

```js
export function createMbc1(rom, header) {
  const romBanks = header.romBanks;          // power of two
  const ram = new Uint8Array((header.ramKiB || 0) * 1024);
  let ramEnable = false;
  let romBank = 1;
  let ramBank = 0;
  let mode = 0;

  function mapRom00() {
    // Mode 0: always bank 0. Mode 1: banks 0x00/0x20/0x40/0x60.
    if (mode === 0) return 0;
    return ((ramBank & 3) << 5) & (romBanks - 1);
  }

  function mapRom40() {
    // Both modes: 2 upper bits | 5-bit ROM bank (already 1..31).
    return ((ramBank & 3) << 5 | (romBank & 0x1f)) & (romBanks - 1);
  }

  return {
    readRom(addr) {
      if (addr < 0x4000) {
        const b = mapRom00();
        return rom[b * 0x4000 + addr];
      }
      const b = mapRom40();
      return rom[b * 0x4000 + (addr - 0x4000)];
    },
    writeRom(addr, v) {
      if (addr < 0x2000) ramEnable = (v & 0x0f) === 0x0a;
      else if (addr < 0x4000) romBank = (v & 0x1f) || 1;
      else if (addr < 0x6000) ramBank = v & 0x03;
      else mode = v & 0x01;
    },
    readRam(addr) { /* $FF if !ramEnable || ram.length === 0; else ram[offset] */ },
    writeRam(addr, v) { /* if enabled */ },
  };
}
```

64 KiB (4 banks): `ramBank` is irrelevant. Super Mario Land only exercises `romBank` 1–3 and the “0 → 1” quirk.

Always mask with `(romBanks - 1)` so a 64 KiB cart wrapping `$05` does not read past `rom.length`.

## SRAM

Types `$02`/`$03`: allocate `ramKiB * 1024` bytes. Offset:

```
offset = ramOffset + (addr - 0xa000)
ramOffset = (mode === 1 ? ramBank : 0) * 0x2000
```

2 KiB RAM: only `$A000–$A7FF` is real (`addr & 0x1fff` wrap 0x800). Battery (`$03`) persistence waits until chapter 14’s `localStorage` helper — you can already keep the `Uint8Array` alive across Reset in memory.

## Pitfalls

- **Bank 0 in `$4000`:** `romBank = value & 0x1f` without `|| 1`. Mario Land will jump into bank 0 twice and crash or loop the header.
- Using `rom[addr]` for `$4000–$7FFF` still.
- `romBanks` from file length (`rom.length / 0x4000`) vs header — prefer header, assert they match.
- Mutating `rom` on writes.
- Forgetting ROM-only carts: `createCart` must still serve Tetris.

## Checkpoint

Header for Super Mario Land: `MBC1`, 64 KiB, no RAM.

Boot: Nintendo logo leftover in VRAM may flash; then the title / gameplay. Walk right. If you freeze on a black screen after a jump, you likely mapped bank 0. Log `romBank` on every write to `$2000–$3FFF`.

Regression: Tetris still plays.
